### Phase 1: Primitives (6 components)

All six W31 Batch K primitives were built in `src/shared/ui/`:

**`AIFeedbackBar`** — Thumbs up/down vote bar for AI recommendations. Three states: neutral, positive, negative. When a vote is cast, an optional free-text prompt slides in for elaboration. testID pattern: `${testID}-positive`, `-negative`, `-freetext`, `-submit`, `-thanks`.

**`ExplainabilitySheet`** — "Why did I get this?" bottom sheet wrapping `ModalSheet`. Renders reason chips in a horizontal scroll row, an explanation paragraph, a "Got it" dismiss CTA, and an optional "Opt out of AI suggestions" link. Props: `visible`, `explanation`, `reasons[]`, `onDismiss`, `onOptOut`.

**`ChannelPreferenceMatrix`** — 8 notification event types × 3 channels (push/email/SMS) rendered as a scrollable grid of `Switch` cells. Each cell testID is `${testID}-{eventType}-{channel}`. The `onToggle(channel, eventType, enabled)` callback propagates changes to the parent.

**`TierUpCelebration`** — Full-screen `Modal` celebration overlay. Shows confetti placeholder, tier badge, a congratulations headline, an optional benefit subtitle, and a "Explore benefits" CTA. Props: `visible`, `newTier: LoyaltyTier`, `benefitHeadline?`, `onDismiss`.

**`FollowToggle`** — Optimistic follow/unfollow button. Flips state immediately on press; if `onToggle` returns a Promise, shows a small activity indicator. On rejection, rolls back the optimistic state. Props: `followed`, `onToggle(following: boolean)`, `size?: "sm" | "md"`.

**`WalkInForm`** — Walk-in client capture form. States: default → submitting → success / error. Service multi-select uses chip buttons. Collected fields: name, phone, notes, services. Props: `services[]`, `formState?`, `errorMessage?`, `onSubmit(data)`, `onReset?`.

Minor bug fixed during `WalkInForm` creation: `useState` was originally inside the component body rather than at the top import — corrected before committing.

### Phase 5: TypeScript Fixes (15 errors → 0)

`npx tsc --noEmit` surfaced 15 errors across 6 files. All were prop-name mismatches:

- **`ModalSheet.onDismiss` → `onClose`** — affected every file using `ModalSheet` (5 usages). The actual prop has always been `onClose`.
- **`colors.accentSubtle` → `colors.background`** — no `accentSubtle` token exists; 4 style references replaced with `colors.background`.
- **`RewardCard`** — `pointsCost` does not exist (prop is `points`); `state="available"` is not a valid `RewardCardState` (changed to `"unlocked"`).
- **`SummaryRow.highlighted`** — no such prop; removed.
- **`LegalPageLayout.onClose`** — actual prop is `onBack`; corrected.
- **`SearchSuggestionRow.subLabel`** — not in the type; removed.
- **`PreferenceToggleRow.subLabel`** — actual prop is `helperText`; corrected.
- **`ReceiptLineItem` `label`/`value`** — actual props are `description`/`amountLabel`; corrected.

After fixes, `npx tsc --noEmit` exited cleanly with no output.

### Phase 6: Jest Fixes (5 failures → 0)

`npx jest --no-coverage __tests__/w31*` initially failed on two issues:

1. **Import paths** — all 6 test files used `../../src/...` but should use `../src/...` from the root `__tests__/` directory. Fixed via a bulk `Get-Content` / `-replace` / `Set-Content` pass.

2. **`LoyaltyTermsPage` duplicate text** — `LegalPageLayout` renders section headings both in the jump-link scroll row and as section headers in the content, so `getByText("Earning points")` found multiple elements for 4 of the 5 heading tests. Fixed by switching affected assertions to `getAllByText(...).length`.toBeGreaterThan(0).

3. **`ChannelPreferencesScreen` async error state** — `getByTestId("cps-error")` wasn't found because the rejected promise state update happened after the test's synchronous assertions. Fixed by importing `waitFor` and wrapping the assertion: `await waitFor(() => expect(getByTestId("cps-error")).toBeTruthy())`.

After fixes, all 165 W31 tests passed. Full suite confirmed at **2,556 / 154 suites — all green**.

## Issues and Lessons

- **`ModalSheet` prop name** — Every new file used `onDismiss` by muscle memory but the component uses `onClose`. This pattern needs to be noted for future batches.
- **Token safety** — `colors.accentSubtle` was invented and used in 4 files. Before using a color token, check the actual token object.
- **RewardCard props** — `pointsCost`/`available` are logical name guesses that don't match the actual API (`points`/`unlocked`). Always grep the source before using.
- **Test async patterns** — `await Promise.resolve()` × 2 is not sufficient for rejected-promise state updates. Use `waitFor` from testing-library for async state changes driven by thrown errors.
- **Duplicate text in complex layouts** — `LegalPageLayout` renders jump link labels AND section heading text. Use `getAllByText` when the component is known to duplicate labels.
