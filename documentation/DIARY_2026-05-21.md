## Decisions Made
1. Decision: Use `displayName ?? name` (not `name ?? displayName`) for tenant name fallback in the suspend flow.
   - Why: `displayName` is the "pretty" label shown on TenantDetailScreen; `name` is the always-present canonical field. The suspend confirmation should show the same label the admin just saw.
   - Impact: Consistent tenant name rendering across detail and suspend flows.

2. Decision: Add `defaultTenantId?: string` to `ImpersonationScreen` props (Option B) rather than silently dropping the prop.
   - Why: The shell was always trying to pre-fill the tenant ID — the intent was clear. Option A (drop the prop) would have made that intent invisible and forced admins to retype a value they already knew.
   - Impact: Admin only needs to enter User ID; Tenant ID is pre-filled from TenantDetail context.

3. Decision: Log the impersonation runtime gap (missing reason/email) as NEW-DEBT-L (high severity) rather than fix in this session.
   - Why: Fixing requires a UX decision about new form fields — out of scope for a TypeScript cleanup task.
   - Impact: Feature remains non-functional at runtime (was already broken before this session).
